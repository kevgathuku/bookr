Waitlist and late cancels

Win: full classes queue fairly, cancellations free seats into the queue automatically, and late cancels are marked — not refunded, not ignored.

Lesson 4 booked seats. This lesson ends bookings: waitlists, holds, cancels, no-shows. One deliberate omission: money. Cancelling here flips status and promotes the next waiter, but moves no credits — the ledger does not exist yet. Lesson 6 wires the refund and the promotion charge into exactly the seams marked below, and you will see why the seams were left visible. Resist the urge to build money early; the lifecycle must be correct before it is valuable.

Step 1 — Holds: one field, one task

When a seat frees, the longest-waiting member gets a time-limited hold — not the seat outright, because they might be asleep. Add the field (its own migration):

    hold_until = models.DateTimeField(null=True, blank=True)

The promotion itself runs in a Celery task, for two reasons that both matter now. First, cancellation should return fast while promotion does several writes. Second, testability: Celery's eager mode runs tasks inline, so tests exercise the real path without a broker. Development needs no broker at all — the setting defaults to eager, and the worker moves into compose in lesson 11:

# config/settings/base.py
CELERY_BROKER_URL = os.environ.get("CELERY_BROKER_URL", "redis://localhost:6379/0")
CELERY_TASK_ALWAYS_EAGER = os.environ.get("CELERY_EAGER", "1") == "1"
# booking/tasks.py
from celery import shared_task


@shared_task(name="booking.promote_waitlist")
def promote_waitlist(booking_id=None, class_id=None):
    """Promote the longest-waiting waiter into a free seat. Natural no-op
    when full or empty, so retries are safe."""
    if (booking_id is None) == (class_id is None):
        raise ValueError("Pass exactly one of booking_id, class_id.")
    if class_id is None:
        trigger = Booking.objects.select_related("scheduled_class").get(pk=booking_id)
        class_id = trigger.scheduled_class_id
        if class_id is None:
            return 0
    with transaction.atomic():
        locked = ScheduledClass.objects.select_for_update().get(pk=class_id)
        if not _free_seat(locked):
            return 0
        first = (
            Booking.objects.select_for_update()
            .filter(scheduled_class=locked, status=Booking.Status.WAITLISTED)
            .order_by("created_at")
            .first()
        )
        if first is None:
            return 0
        return _promote(first)

Three patterns to steal. The task takes either trigger id or class id and refuses both/neither — one entry point for cancels, sweeps, and admin actions. Every exit that changes nothing returns 0 instead of raising, so retries and double-delivery are harmless (message queues deliver at-least-once; your tasks must assume it). And both the class and the waiter row are locked: the free-seat check and the promotion happen atomically, or two concurrent promotes hand out one seat twice. _promote confirms the waiter and stamps hold_until from the venue policy's waitlist_hold_minutes — and leaves an explicit seam where lesson 6 charges the waiter's pass:

def _promote(first):
    # Lesson 6 wires the charge here: spend the waiter's credit, so a
    # lapsed pass keeps them queued and the seat stays open.
    minutes = first.venue.current_policy.waitlist_hold_minutes
    first.status = Booking.Status.CONFIRMED
    first.hold_until = timezone.now() + timezone.timedelta(minutes=minutes)
    first.save(update_fields=["status", "hold_until"])
    notify.booking_promoted(first)
    return 1

The sweeper reclaims lapsed holds on a beat (nightly in production; freezegun in tests). Same shape — lock, re-check under the lock, act — because the member might confirm between listing and locking:

@shared_task(name="booking.sweep_expired_holds")
def sweep_expired_holds():
    """Beat sweeper: lapsed holds cancel and the seat passes to next."""
    now = timezone.now()
    swept = 0
    held = Booking.objects.filter(
        status=Booking.Status.CONFIRMED, hold_until__lt=now
    ).select_related("scheduled_class")
    for booking in held:
        with transaction.atomic():
            locked = Booking.objects.select_for_update().get(pk=booking.pk)
            if locked.status != Booking.Status.CONFIRMED or (
                locked.hold_until is not None and locked.hold_until >= now
            ):
                continue
            locked.status = Booking.Status.CANCELLED
            locked.hold_until = None
            locked.save(update_fields=["status", "hold_until"])
            swept += 1
            if locked.scheduled_class_id is not None:
                promote_waitlist.delay(class_id=locked.scheduled_class_id)
    return swept

Step 2 — Cancel, no-show, and the strike flag

One service owns every ending (booking/cancellations.py), with the same lock-then-act discipline. Member cancel under the venue's window cancels; inside it marks late — and late is a status, not a refund decision, because money does not exist yet. Staff override skips the window (front desk needs it for real life); it takes a mandatory reason, stored in lesson 9's ledger note:

def cancel_booking(actor, booking, *, staff_override=False, reason=""):
    """Cancel inside a transaction; frees the seat and triggers promotion."""
    with transaction.atomic():
        locked = (
            Booking.objects.select_for_update(of=("self",))
            .select_related("scheduled_class", "appointment", "venue")
            .get(pk=booking.pk)
        )
        if locked.status not in (
            Booking.Status.CONFIRMED,
            Booking.Status.WAITLISTED,
        ):
            raise ValidationError("Booking is already closed.")
        freed = locked.status == Booking.Status.CONFIRMED
        if staff_override:
            locked.status = Booking.Status.CANCELLED
        else:
            target = _target(locked)
            cutoff = target.starts_at - timedelta(hours=_window_hours(locked))
            if timezone.now() <= cutoff:
                locked.status = Booking.Status.CANCELLED
                notify.booking_cancelled(locked)
            else:
                locked.status = Booking.Status.CANCELLED_LATE
                notify.booking_late_cancel(locked)
        locked.save(update_fields=["status"])
        if freed and locked.scheduled_class_id is not None:
            from booking.tasks import promote_waitlist

            promote_waitlist.delay(booking_id=locked.pk)
    return locked

The function-level import of promote_waitlist is deliberate: booking/tasks.py imports the service layer, so a top-level import would cycle. No-show forfeits without refund (front desk marks within 2h after end; outside that window the mark is refused), and the strike flag counts late-cancels plus no-shows in 30 days — flag, never auto-ban, because banning is a human decision:

Step 3 — Mail that cannot break booking

Notices send through Django mail — console backend in dev and test (assert via mail.outbox), SMTP in production. One rule learned the hard way in the dress rehearsal: sending must be best-effort. An SMTP outage once turned every cancel into a 500, because the send ran inside the booking transaction. Now each notice catches its own failure and logs it:

def _send(subject, body, to):
    # Best-effort: a mail outage must never fail the booking write.
    try:
        send_mail(subject, body, None, [to])
    except Exception:
        logger.exception("member notice failed")

Step 4 — Endpoints and the boundary tests

Three endpoints: GET /api/v1/bookings/?mine=true (own bookings, newest first), POST .../<id>/cancel/ (staff override via {"staff_override": true, "reason": ...}, reason mandatory), POST .../<id>/no-show/. Then the tests that earn the lesson: the FIFO test (cancel → first waiter confirmed with a hold, mail in outbox), the boundary test (cancel at window ±1 minute → cancelled vs cancelled_late — pick class times arithmetically, never "about an hour"), and the hold-expiry test with freezegun (freeze past hold_until, sweep, seat passes to next).

Exercises
