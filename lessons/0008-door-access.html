Door access

Win: a knock on POST /api/access/check gets grant/deny in under 200ms — and an outage never opens the door.

Step 1 — New app, then the check (read-only)

uv run python manage.py startapp access, add it to INSTALLED_APPS. Models: AccessPoint (controller id per venue), AccessEvent (every knock with its reason). The view deducts nothing — it only reads:

def access_check(request):
    member = identify(request)          # per-controller token auth
    grant = has_active_pass(member) \
        or has_live_booking(member, window=(-15, +duration)) \
        or is_staff(member)
    AccessEvent.objects.create(member=member, access_point=...,
        granted=grant, reason=...)
    return JsonResponse({"granted": grant})

Keep the hot path lean (skip DRF serialization if profiling says so). Anti-passback: same member within ~60s replays the prior decision without a new row.

Step 2 — Cache + fail closed

Cache member validity in Redis (60s TTL), DB fallback underneath — configured once in CACHES (django.core.cache.backends.redis.RedisCache), after which Django's cache API is identical whatever the backend. Then the drill that matters: kill the database in staging and knock — the door must deny + log, never hang or open. Fail-closed is a tested behavior, not a belief. Load-test to p95 < 200ms (k6 or locust).

Step 3 — Expose + observe

Recent events visible to frontdesk; emit the door_grants_total metric. E2E #2: upcoming booking → grant; expired pass + no booking → deny; assert both rows exist in AccessEvent.

Deliverables — check them off
