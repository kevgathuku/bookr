Credit ledger — MVP done

Win: every credit movement is auditable, races can't double-spend — and with this lesson the MVP is shippable.

Step 1 — Ledger models

PassProduct (credits or unlimited, validity, applicable class-type M2M blank = all), MemberPass (member's instance, cached counters), append-only CreditLedger (pass, booking, ±delta, reason, actor, timestamp). Balance is always SUM(delta) — cached counters update in the same transaction, history is never edited. Note: the spec's pass field is member_pass in code (pass is a Python keyword).

Step 2 — Spend, refund, expire

passes/services.py::spend_credit(member, booking): lock the chosen pass (select_for_update), oldest valid pass covering the class type first, unlimited passes before credit bundles. Pair it with refund_credit, reason-required adjust_credit, and a nightly beat task expire_passes writing expiry rows:

def spend_credit(member, booking):
    with transaction.atomic():
        p = (MemberPass.objects.select_for_update()
             .filter(member=member, status="active",
                     valid_until__gt=now())
             .order_by("valid_until").first())  # FIFO; unlimited-first is a second pass
        if p is None:
            raise CreditInsufficient
        CreditLedger.objects.create(member_pass=p, booking=booking,
            delta=-1, reason="booking")
        p.credits_used += 1  # cache only
        p.save()

Step 3 — Wire it into lessons 4–5

Replace the stubs: book_seat calls spend_credit; cancel_booking calls refund_credit or writes a forfeit row per the window rules. Expose GET /api/v1/me/passes plus the ledger view (members see own, frontdesk sees the gym's). Then run both races again: last-seat and last-credit (20 threads × 1 credit → exactly 1 booking), plus the invariant test — ledger sums equal cached balances on seed data.
