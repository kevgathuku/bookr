Tests, CI, ship

Win: a suite you trust and a pipeline that runs it — green CI on a fresh clone, following only this course.

Step 1 — New dev deps, then the layout

uv add --dev pytest pytest-django factory-boy freezegun playwright ruff black mypy. Grow the day-one tests/ (lesson 2) per the testing cheatsheet: tests/unit (services, ledger math, generate_slots — pytest-django + factory-boy + freezegun, ≥80% on services), tests/api (status codes, cross-venue 404s, idempotent retries), tests/e2e (Playwright @e2e against the running app + mailpit asserts). Move the lesson-4/6 race tests into unit — marked @pytest.mark.django_db(transaction=True) per lesson 4's TransactionTestCase rule — they run in CI, not just once. Point pytest at Django once, in pyproject.toml ([tool.pytest.ini_options], DJANGO_SETTINGS_MODULE), and add a factory per model (start with Venue, User, ScheduledClass, MemberPass).

Step 2 — Pipeline

GitHub workflow, in order (each gate blocks the next):

ruff + black --check  →  mypy (services, models)  →
pytest -x  →  playwright @smoke

Full @e2e runs nightly + pre-release, not per-commit. Check: push a branch with a deliberately broken race test and watch CI go red at the right gate.

Step 3 — Ship checklist

Work it top to bottom, checking each: sqlmigrate output reviewed (especially the exclusion constraints); seed-from-zero rebuilds everything (rm the db, migrate, seed_demo); /healthz + Sentry + structured logs (venue_id/booking_id on every line); token-rotation runbook written; fail-closed drill done (lesson 9); postmortem template written before you need it.
