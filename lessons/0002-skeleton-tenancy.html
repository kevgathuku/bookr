Skeleton and multi-tenancy

Win: docker compose up gives web + db + redis + worker, and every row belongs to exactly one gym.

Steps

  1. django-admin startproject config ., then one app per domain: gyms members scheduling bookings passes aggregators access. Don't merge them — you'll regret it at lesson 7.
  2. Compose stack: web, Postgres (with btree_gist), redis, celery worker, beat, mailpit. Settings split via django-environ: base/dev/prod. UTC in the database; per-gym time zone for display only.
  3. Tenancy core: Gym (slug, policy knobs: late_cancel_h=8, appt_late_cancel_h=24, hold_ttl_min=60, buffer_min=10), a queryset mixin filtering by gym, middleware resolving the gym, per-gym unique constraints.
  4. Roles via Membership(user, gym, role) and an IsGymMember permission — cross-gym access returns 404, not 403 (see glossary).
