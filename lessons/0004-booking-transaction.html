The booking transaction

Win: exactly one member gets the last seat, even with 20 racers. If this fails, stop — nothing later matters.

Steps

  1. Booking with unique idempotency_key plus a partial unique constraint: one active booking per member per class. This is the primary seam (see testing cheatsheet).
  2. One function creates bookings: book_seat(member, klass, waitlist=False, idempotency_key). Transaction + row lock on the class → count confirmed → full? raise SeatFull (view → 409, offer ?waitlist=true) → else spend credit (stubbed until lesson 6) → create. Fat service, thin views.
  3. Views map typed errors to codes: SeatFull→409, CreditInsufficient→402, DuplicateBooking→409. No business logic in views or serializers.
