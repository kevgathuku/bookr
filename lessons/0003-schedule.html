Schedule that can't double-book

Win: staff publish classes, and the database itself refuses overlapping room or teacher bookings.

Step 1 — Models

In scheduling/models.py: ClassType (name, capacity_default, duration_min), Room (name, capacity), ScheduledClass (type, room, teacher, starts/ends, capacity_override, status, checkin_opens_min=30), append-only TeacherSubstitution (old/new teacher, reason — never rewrite history). Capacity resolves override → room → type default; shrinking capacity never ejects confirmed bookings (enforce in the service, lesson 4).

Step 2 — The constraint (the important line)

On ScheduledClass.Meta, one exclusion per scope — same room or same teacher, overlapping time, both non-cancelled. Django 6 note: CheckConstraint takes condition=, not check=:

from django.contrib.postgres.constraints import ExclusionConstraint
from django.contrib.postgres.fields import DateTimeRangeField, RangeOperators
from django.db.models import F, Func, Q

def _range():
    return Func(F("starts_at"), F("ends_at"),
                function="TSTZRANGE", output_field=DateTimeRangeField())

class Meta:
    constraints = [
        ExclusionConstraint(name="no_double_room",
            expressions=[("gym", RangeOperators.EQUAL),
                         ("room", RangeOperators.EQUAL),
                         (_range(), RangeOperators.OVERLAPS)],
            condition=~Q(status="cancelled")),
        ExclusionConstraint(name="no_double_teacher",
            expressions=[("gym", RangeOperators.EQUAL),
                         ("teacher", RangeOperators.EQUAL),
                         (_range(), RangeOperators.OVERLAPS)],
            condition=~Q(status="cancelled")),
    ]

Run makemigrations, then read the migration's sqlmigrate output by eye — this is the constraint that saves you at 6pm on Monday. It needs btree_gist (lesson 2's DB init script).

Step 3 — Prove the refusal

In the shell (uv run python manage.py shell, seed data loaded): create two overlapping classes in the same room. The second must raise IntegrityError. Same teacher, different rooms, overlapping time → also refused. Cancelled overlapping classes → allowed.

Step 4 — List endpoint

DRF read view: GET /api/v1/classes?from=&to=, bounded (reject ranges > 31 days), select_related("class_type", "room", "teacher"), gym-scoped queryset from lesson 2's mixin. Staff-only POST/PATCH for publishing. Cancelling sets cancelled and fires a stub Celery task (real refund/notify/promote lands in lesson 5 — log a line for now). Substitution POST creates the row, keeps the old teacher, notifies (console backend for now). Check query count with assertNumQueries(≤3) on the list test.
