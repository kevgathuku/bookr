Schedule that can't double-book

Win: staff publish classes, and the database itself refuses overlapping room or teacher bookings.

Step 1 — New app, then models

uv run python manage.py startapp scheduling, add it to INSTALLED_APPS, delete its stubs. Then in scheduling/models.py: ClassType (name, capacity_default, duration_min), Room (name, capacity), ScheduledClass (type, room, teacher, starts/ends, capacity_override, status, checkin_opens_minutes=30), append-only TeacherSubstitution (old/new teacher, reason — never rewrite history). Capacity resolves override → room → type default; shrinking capacity never ejects confirmed bookings (enforce in the service, lesson 4). Everything here belongs to exactly one venue — schedules are never shared across venues.

Step 2 — The constraint (the important line)

On ScheduledClass.Meta, one exclusion per scope — same room or same teacher, overlapping time, both non-cancelled. Django 6 note: CheckConstraint takes condition=, not check=:

from django.contrib.postgres.constraints import ExclusionConstraint
from django.contrib.postgres.fields import DateTimeRangeField, RangeOperators
from django.db.models import F, Func, Q

def _range():
    return Func(F("starts_at"), F("ends_at"),
                function="TSTZRANGE", output_field=DateTimeRangeField())

class Meta:
    constraints = [
        ExclusionConstraint(name="no_double_room",
            expressions=[("venue", RangeOperators.EQUAL),
                         ("room", RangeOperators.EQUAL),
                         (_range(), RangeOperators.OVERLAPS)],
            condition=~Q(status="cancelled")),
        ExclusionConstraint(name="no_double_teacher",
            expressions=[("venue", RangeOperators.EQUAL),
                         ("teacher", RangeOperators.EQUAL),
                         (_range(), RangeOperators.OVERLAPS)],
            condition=~Q(status="cancelled")),
    ]

Run makemigrations, then read the migration's sqlmigrate output by eye — this is the constraint that saves you at 6pm on Monday. It needs btree_gist (lesson 2's CREATE EXTENSION). Django nuance: constraints are DDL — makemigrations writes them, sqlmigrate shows the SQL, and SQLite silently skips what it can't express, which is why this course develops against Postgres from day one.

Step 3 — Prove the refusal

In the shell (uv run python manage.py shell, seed data loaded): create two overlapping classes in the same room. The second must raise IntegrityError. Same teacher, different rooms, overlapping time → also refused. Cancelled overlapping classes → allowed. Then extend seed_demo with one room and one class — later lessons build on it.

Step 4 — List endpoint

Install DRF (uv add djangorestframework) and add the read view: GET /api/v1/classes?from=&to=, bounded (reject ranges > 31 days), select_related("class_type", "room", "teacher"). First venue-scoped list, so first shared tool for it — define the mixin here, not earlier (nothing before this lesson queried by venue):

class VenueQuerySet(models.QuerySet):
    def for_venue(self, venue):
        return self.filter(venue=venue)

class ScheduledClass(models.Model):
    ...
    objects = VenueQuerySet.as_manager()  # the trick: queryset becomes the default manager

Every later scoped model reuses it (Model.objects.for_venue(request.venue)). Staff-only POST/PATCH for publishing. Cancelling sets cancelled and logs a fan-out line (it becomes a Celery task in lesson 5). Substitution POST creates the row, keeps the old teacher, notifies (console backend for now). Check query count with assertNumQueries(≤3) on the list test.
