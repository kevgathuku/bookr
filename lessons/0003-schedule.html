Schedule that can't double-book

Why PROTECT on room, type, and teachers: deleting a room with classes on the books must fail loudly, not cascade into silent data loss. Why the ClassVar annotations on Meta lists: ruff's RUF012 flags mutable class attributes — the annotation marks them as intentional class-level state (see lesson 2's lineage).

Step 2 — ScheduledClass and the constraint (the important lines)

from typing import ClassVar

from django.conf import settings
from django.contrib.postgres.constraints import ExclusionConstraint
from django.contrib.postgres.fields import DateTimeRangeField, RangeOperators
from django.db import models
from django.db.models import F, Func, Q


def _time_range():
    # TSTZRANGE(starts_at, ends_at): one overlap-testable value for &&.
    return Func(
        F("starts_at"), F("ends_at"),
        function="TSTZRANGE", output_field=DateTimeRangeField(),
    )


def _no_overlap(*scope_cols):
    # Same scope + overlapping time, both non-cancelled. The equality
    # columns need btree_gist (lesson 2's database has it).
    return ExclusionConstraint(
        name=f"no_overlap_{'_'.join(scope_cols)}",
        expressions=[(c, RangeOperators.EQUAL) for c in scope_cols]
        + [(_time_range(), RangeOperators.OVERLAPS)],
        condition=~Q(status="cancelled"),
    )


class ScheduledClass(models.Model):
    class Status(models.TextChoices):
        SCHEDULED = "scheduled", "Scheduled"
        CANCELLED = "cancelled", "Cancelled"
        COMPLETED = "completed", "Completed"

    venue = models.ForeignKey(
        "organizations.Venue", on_delete=models.CASCADE, related_name="scheduled_classes"
    )
    class_type = models.ForeignKey(
        ClassType, on_delete=models.PROTECT, related_name="scheduled_classes"
    )
    room = models.ForeignKey(
        Room, on_delete=models.PROTECT, related_name="scheduled_classes"
    )
    teacher = models.ForeignKey(
        settings.AUTH_USER_MODEL, on_delete=models.PROTECT, related_name="taught_classes"
    )
    starts_at = models.DateTimeField()
    ends_at = models.DateTimeField()
    capacity_override = models.PositiveSmallIntegerField(null=True, blank=True)
    status = models.CharField(
        max_length=16, choices=Status.choices, default=Status.SCHEDULED
    )
    checkin_opens_minutes = models.PositiveSmallIntegerField(default=30)

    class Meta:
        indexes: ClassVar[list[models.Index]] = [
            models.Index(fields=["venue", "starts_at"]),
        ]
        constraints: ClassVar[list[models.BaseConstraint]] = [
            models.CheckConstraint(
                condition=Q(ends_at__gt=F("starts_at")),
                name="class_ends_after_starts",
            ),
            _no_overlap("venue", "room"),
            _no_overlap("venue", "teacher"),
        ]

    def effective_capacity(self):
        # Override wins, then room, then type default — and shrinking the
        # answer never ejects confirmed bookings (enforced in lesson 4's service).
        return (
            self.capacity_override
            or (self.room.capacity if self.room_id else None)
            or self.class_type.capacity_default
        )

Django 6 notes that bite here: CheckConstraint takes condition=, not check=; each exclusion needs a unique name (hence the helper building it from the scope columns). One shared helper for both scopes — not two handwritten constraints — so room and teacher can never drift apart.

Step 3 — Prove the refusal, in tests

No shell session — the refusal is a guarantee, so it gets tests (tests/test_scheduling.py). Six hand-built objects per test is already noise, so factories enter here — install once, never write setup boilerplate again: The Django nuance that makes these work: a bare IntegrityError poisons the test's own transaction, so each refusal runs inside an inner transaction.atomic() — a savepoint that rolls back just the failed insert:

uv add --dev factory-boy

Then tests/factories.py — one factory per model, each later lesson extending the file. The trick worth learning is SelfAttribute: the class, room, and teacher must all belong to one venue, so the sub-factories reach back up to it:

import factory
from datetime import timedelta

from django.contrib.auth import get_user_model
from django.utils import timezone

from organizations.models import Organization, Venue
from scheduling.models import ClassType, Room, ScheduledClass


class OrganizationFactory(factory.django.DjangoModelFactory):
    class Meta:
        model = Organization

    slug = factory.Sequence(lambda n: f"org-{n}")
    name = factory.Sequence(lambda n: f"Org {n}")


class VenueFactory(factory.django.DjangoModelFactory):
    class Meta:
        model = Venue

    organization = factory.SubFactory(OrganizationFactory)
    slug = factory.Sequence(lambda n: f"venue-{n}")
    name = factory.Sequence(lambda n: f"Venue {n}")


class UserFactory(factory.django.DjangoModelFactory):
    class Meta:
        model = get_user_model()

    username = factory.Sequence(lambda n: f"user-{n}")


class ClassTypeFactory(factory.django.DjangoModelFactory):
    class Meta:
        model = ClassType

    venue = factory.SubFactory(VenueFactory)
    name = factory.Sequence(lambda n: f"Class {n}")
    duration_min = 60


class RoomFactory(factory.django.DjangoModelFactory):
    class Meta:
        model = Room

    venue = factory.SubFactory(VenueFactory)
    name = factory.Sequence(lambda n: f"Room {n}")
    capacity = 20


class ScheduledClassFactory(factory.django.DjangoModelFactory):
    class Meta:
        model = ScheduledClass

    venue = factory.SubFactory(VenueFactory)
    # SelfAttribute: share the venue above instead of building three more.
    class_type = factory.SubFactory(
        ClassTypeFactory, venue=factory.SelfAttribute("..venue"))
    room = factory.SubFactory(
        RoomFactory, venue=factory.SelfAttribute("..venue"))
    teacher = factory.SubFactory(UserFactory)
    starts_at = factory.LazyFunction(timezone.now)
    ends_at = factory.LazyAttribute(
        lambda o: o.starts_at + timedelta(minutes=60))

The tests shrink to intent. The Django nuance that makes the refusal cases work: a bare IntegrityError poisons the test's own transaction, so each runs inside an inner transaction.atomic() — a savepoint rolling back just the failed insert:

import pytest
from datetime import timedelta

from django.db import IntegrityError, transaction

from tests.factories import RoomFactory, ScheduledClassFactory


@pytest.mark.django_db
class TestNoDoubleBooking:
    def test_overlapping_same_room_refused(self):
        klass = ScheduledClassFactory()

        with pytest.raises(IntegrityError), transaction.atomic():
            ScheduledClassFactory(
                venue=klass.venue, class_type=klass.class_type,
                room=klass.room, teacher=klass.teacher,
                starts_at=klass.starts_at + timedelta(minutes=30))

    def test_overlapping_same_teacher_different_rooms_refused(self):
        klass = ScheduledClassFactory()
        other = RoomFactory(venue=klass.venue)

        with pytest.raises(IntegrityError), transaction.atomic():
            ScheduledClassFactory(
                venue=klass.venue, class_type=klass.class_type,
                room=other, teacher=klass.teacher,
                starts_at=klass.starts_at + timedelta(minutes=30))

    def test_cancelled_overlap_allowed(self):
        klass = ScheduledClassFactory(status="cancelled")

        replacement = ScheduledClassFactory(
            venue=klass.venue, class_type=klass.class_type,
            room=klass.room, teacher=klass.teacher,
            starts_at=klass.starts_at)  # no error

        assert replacement.pk is not None

    def test_back_to_back_allowed(self):
        # TSTZRANGE is [inclusive, exclusive): end == next start is fine.
        klass = ScheduledClassFactory()

        second = ScheduledClassFactory(
            venue=klass.venue, class_type=klass.class_type,
            room=klass.room, teacher=klass.teacher,
            starts_at=klass.ends_at)  # no error

        assert second.pk is not None

Step 5 — First wired requests

The list endpoint is the course's first real request, so the request machinery lives here — lesson 2 had models but nothing to route through them:

5a — Middleware: resolve the venue once, in one place

class VenueMiddleware:
    def __init__(self, get_response):
        self.get_response = get_response

    def __call__(self, request):
        request.venue = self._resolve(request)  # None → every scoped view 404s
        # Derive, don't trust: the org always comes from the venue, never
        # from a second header — two client-controlled headers will disagree.
        request.organization = request.venue.organization if request.venue else None
        return self.get_response(request)

    def _resolve(self, request):
        if request.user.is_authenticated:
            # Staff browser sessions carry a user: their (single) venue wins.
            if membership := Membership.objects.filter(
                    user=request.user).only("venue").first():
                return membership.venue
        # API clients (aggregators, door controllers in later lessons)
        # carry no user — only a header. Fall back to it, not the reverse:
        # a logged-in user must never escape into another venue by header.
        if slug := request.headers.get("X-Venue-Slug"):
            return Venue.objects.filter(slug=slug).first()
        return None

Why middleware instead of per-view logic: tenancy is a request-wide fact, and scattering twelve copies of it across views guarantees the thirteenth view forgets. One choke point means every scoped queryset starts from request.venue the same way. Why staff-first, header-second: headers are client-controlled, so an authenticated user must not be able to header their way into someone else's venue.

5b — Permission: deny outsiders with 404, not 403

class IsVenueMember(BasePermission):
    def has_permission(self, request, view):
        if request.venue is None or not request.user.is_authenticated:
            return False
        return Membership.objects.filter(
            user=request.user, organization=request.organization
        ).filter(Q(venue__isnull=True) | Q(venue=request.venue)).exists()

Wire it into the class viewset, which filters its queryset to request.venue before permission runs — so an org-B member asking for org-A's class 42, or a venue-B-pinned member asking for venue-A's, gets 404 exactly as if 42 didn't exist. The spanning-or-pinned Q is the whole scope model in one query: org must match, and then either the row covers everything or it names this venue. Why not the more truthful 403: a 403 confirms the object is real, which lets anyone enumerate other organizations' records one id at a time (glossary). A 404 reveals nothing. Prove it with three tests: org-A member on org-B's object → 404; pinned member on venue B → 404; spanning member → 200 on both.
