Appointments and calendar

Win: 1-1 sessions share teachers with group classes without ever double-booking a human — and one calendar shows both.

Group classes are carved in advance; appointments are negotiated into free time. The hard part is that both consume the same teachers, so the no-double-booking rule from lesson 3 must now span two tables — and exclusion constraints cannot span tables. This lesson builds the appointment models, computes (never stores) bookable slots, merges both worlds into one calendar feed, and guards the cross-table clash in Python where the database cannot.

Step 1 — Models: resources, rules, exceptions, appointments

New app code inside scheduling (appointments extend scheduling — same bounded context, no new app): Resource (a room-like bookable: massage table, studio), AvailabilityRule (weekday + start/end + valid range), AvailabilityException (holidays, closures), Appointment (venue, member, teacher, optional resource, times, status). The appointment exclusions mirror lesson 3 — (venue, teacher) and (venue, resource), cancelled-exempt — because the same reasoning applies. Booking grows its second target here: nullable appointment FK plus an exactly-one check (a booking is for a class or an appointment, enforced in clean() since cross-column checks cannot be partial uniques).

Step 2 — Slots are computed, never stored

generate_slots(resource, day, duration_min, teacher=None) returns (start_utc, end_utc) pairs through a pipeline worth memorizing: rules → candidate slots → minus exceptions → minus existing commitments → wall-time dedupe. Storing slots would mean invalidating them on every booking, cancel, and rule change — computing them from rules plus commitments keeps exactly one source of truth. Two subtleties to get right: the venue policy's buffer pads commitments on both sides (back-to-back sessions need breathing room), and DST gaps collapse in wall-time dedupe (a spring-forward hour that does not exist must not produce a phantom slot — there is a test with a real transition date, and it fails if you dedupe in UTC).

Step 3 — The cross-table clash, guarded in Python

Here is the sentence to internalize: exclusion constraints cannot span tables, so Python guards appointment-vs-class here (and book_seat guards the reverse direction for class bookings). Appointment.clean() refuses a teacher holding an overlapping class; book_seat raises TeacherUnavailable when the class teacher holds an overlapping appointment. Both directions, both tested — one direction alone leaves a hole shaped exactly like a busy Tuesday. And book_seat never books appointments (no caller passes one yet): appointment purchase is a later lesson's seam, and the spend function would crash on a class-less booking today — a known gap, not a bug, until that lesson wires it.

Step 4 — One calendar feed, bounded

One serializer addition first: substitution rows carry teacher ids, but readers need names. Two read-only fields (the same source= pattern lesson 3's later endpoints reuse everywhere):

class TeacherSubstitutionSerializer(serializers.ModelSerializer):
    old_teacher_name = serializers.CharField(
        source="old_teacher.username", read_only=True
    )
    new_teacher_name = serializers.CharField(
        source="new_teacher.username", read_only=True
    )

GET /api/v1/calendar?from=&to=&teacher=&room= merges classes and appointments into one event list (kind discriminates), bounded to 31 days like lesson 4's window discipline. Each event carries UTC instants; timezone display is a client concern (venue time_zone travels on the venue payload). Keep it fast with select_related on both querysets and paginate by day — the week view renders hundreds of events, and N+1 here is the first slowdown real users feel. Appointment late-cancel gets its own window (appointment_late_cancel_hours, 24h default — longer than classes because a therapist cannot refill an hour like a group class refills a seat).

Exercises

1. Book a class for a teacher, then insert an overlapping appointment, then reverse the order. Both must refuse — remove one guard and show which order slips through.
2. DST: generate slots for a resource on your zone's spring-forward Sunday. Prove the missing hour produces no slot.
3. Buffer: set the policy buffer to 30 minutes and show two adjacent appointments refuse.
4. Calendar budget: seed 200 classes + 50 appointments, fetch the week feed, assert the query count stays flat.
