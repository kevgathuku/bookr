Docker dress rehearsal

Win: the app you verified locally runs from images on a clean machine — the last step before any cloud.

Step 1 — Image

Install the server (uv add gunicorn), then write a multi-stage Dockerfile: builder runs uv sync --frozen, runtime is slim, runs gunicorn config.wsgi as a non-root user, collectstatic at build time. Rule: no secrets in the image — SECRET_KEY, DATABASE_URL, everything via environment (django-environ already reads them). Check: docker build -t bookr:lesson11 . succeeds; inspect the layers and justify each one.

Step 2 — Prod compose

Grow the compose file: add web/worker/beat (the worker and beat move in from their terminals) and write docker-compose.prod.yml — prod gets gunicorn + the real email sender via EMAIL_URL (dev keeps runserver + mailpit). Migrations are a one-off, never part of boot:

docker compose -f docker-compose.prod.yml up --build -d
docker compose -f docker-compose.prod.yml run --rm web python manage.py migrate
docker compose -f docker-compose.prod.yml run --rm web python manage.py seed_demo  # staging only

Step 3 — Verify like a stranger

Pretend you've never seen this app: /healthz → 200, admin login works, run the @smoke suite against the containers, hand-click one full booking (book → pay credit → cancel → refund visible). Read the logs — every line carries venue_id/booking_id per lesson 9's checklist.

Step 4 — Prove reproducibility

docker compose -f docker-compose.prod.yml down -v   # destroy everything
docker compose -f docker-compose.prod.yml up --build -d
# migrate → smoke → manual booking, all green again

If it isn't green from scratch, it isn't shippable. Write the rollback runbook now: previous image tag + how migrations go backwards.
