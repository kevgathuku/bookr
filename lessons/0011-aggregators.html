Aggregators

Win: a stranger's platform books your seats — within allotment, idempotently, billed to them, never touching member passes. Phase 2: start only after lessons 1–10 are validated; aggregators multiply every booking-path bug onto a partner's platform.

Step 1 — New app (Phase 2), then partner models + auth

uv run python manage.py startapp aggregators, add it to INSTALLED_APPS. Models: Aggregator (slug, hashed token, seat allotment, contract cutoff, commission, active), AggregatorBooking (partner + external id → booking, unique together), AggregatorEventLog (every inbound call — reconciliation evidence). Separate router POST /api/v1/aggregators/<slug>/bookings with per-partner token auth: hash the presented token (sha256) and compare with hmac.compare_digest against api_token_hash — never user passwords, never plain equality (plain == leaks via timing — compare_digest is the stdlib answer). Add throttling.

Step 2 — Book within allotment, idempotently

Enforce min(allotment, free seats), then reuse lesson 4's book_seat (same seats, same locks — aggregators are just another channel):

try:
    return AggregatorBooking.objects.get(
        aggregator=aggregator, external_id=external_id)
except AggregatorBooking.DoesNotExist:
    pass
# NB: get_or_create(defaults={"booking": book_seat(...)}) would run
# book_seat() even on a hit — arguments evaluate before the call.
with transaction.atomic():
    booking = book_seat(...)
    try:
        return AggregatorBooking.objects.create(
            aggregator=aggregator, external_id=external_id, booking=booking)
    except IntegrityError:
        return AggregatorBooking.objects.get(  # lost the race; return the winner
            aggregator=aggregator, external_id=external_id)

Late cancels use the contract cancel_cutoff_minutes, never venue defaults or member passes. Log every request to AggregatorEventLog first — replaying the log must reproduce booking state (that's your reconciliation test).

Step 3 — Outbound feed + rotation

Read-only GET …/schedule?from&to plus HMAC-signed change webhooks via Celery with backoff retries; sign with a per-partner secret and verify signatures in tests. Rotate a token: new hash saved → old token gets 401. Check all four: double external_id → one booking; over allotment → 409; rotated → 401; bad webhook signature → rejected.
